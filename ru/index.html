Примеры работ

Избранные работы 2019–2026 годов, анонимно: без названий компаний, отраслей и абсолютных цифр заказчика.

Пример 1

Kubernetes в AWS: вдвое меньше нод, перезапуски только в согласованном окне

Задача

Несколько EKS-кластеров в нескольких аккаунтах AWS росли органически: фиксированные группы нод под пиковую нагрузку, on-demand везде, пакетные задачи и долгоживущие сервисы на одних и тех же нодах. Один кластер запрашивал около 60 % CPU при использовании около 10 %. Любая автоматическая консолидация нод перезапускала сервисы в произвольное время.

Решение

Перевёл кластеры на Karpenter с консолидацией недозагруженных нод, вынес пакетные задачи в отдельные пулы с защитой от вытеснения политикой, добавил spot-пулы, к которым владельцы сервисов подключаются через toleration. Первый запуск консолидации дал цикл пересоздания ноды; после разбора причин консолидация и ротация нод ограничены одним согласованным окном в сутки, с правилами оповещения о возрасте нод. Все изменения через Terraform/Terragrunt и MR с ревью, раскатка по кластерам по одному с проверкой после каждого.

Результат

Число нод сократилось более чем вдвое, расходы на ноды соответственно. Сервисы перезапускаются только в окне; инциденты из-за консолидации прекратились.

Пример 2

CI на self-hosted GitLab: от bare-metal раннеров, настроенных вручную, к автоскейлящимся флотам

Задача

Нативные сборки шли на нескольких bare-metal раннерах с ручной настройкой. Одна и та же сборка занимала от 7 минут до более часа в зависимости от загрузки хостов, ARM-очередь голодала, диски забивались старыми образами, хранилище артефактов дважды переполнялось и валило джобы. Около 40 % фоновых задач GitLab-сервера уходило на мёртвые вебхуки.

Решение

Спроектировал автоскейлящиеся раннер-флоты в AWS (x86 и ARM, spot), описанные кодом и разворачиваемые через GitOps. Прогнал тестовую неделю на реальных джобах, мигрировал самый тяжёлый проект, затем вывел статические раннеры и переустановил их хосты под вычислительный кластер. Убрал мёртвые вебхуки, ввёл сроки хранения CI-истории и лимиты кэша сборок, написал процедуру апгрейда сервера с проверкой фоновых миграций и передал её команде.

Результат

Статических раннеров не осталось. Хранимых пайплайнов на 58 % меньше, задержка фоновых задач упала с минут до секунд. Плановый апгрейд сервера укладывается в окно около получаса.

Пример 3

Bare-metal кластер под вычисления с большим объёмом данных, управляемый как код

Задача

Команде анализа данных нужны были вычисления с быстрыми локальными дисками и большими объёмами данных, которые в облаке стоили несоразмерно дорого. Требовался кластер на арендованных серверах с той же дисциплиной, что в облаке: воспроизводимая установка, шифрование данных, общий доступ к хранилищу без ключей на хостах.

Решение

Начал с пилота из трёх нод и расширил кластер до более чем пятнадцати: установка и бутстрап через Ansible, RAID0 под рабочие данные, LUKS на разделе с данными, общий бакет объектного хранилища, примонтированный только для чтения на всех нодах через сетевую политику вместо ключей на хостах. Написал процедуру ввода, вывода и переустановки нод и инструкцию для пользователей кластера.

Результат

Партия из десяти нод введена в строй за несколько дней по процедуре, а не по памяти одного человека. Прямое чтение из бакета примерно в семь раз быстрее прежнего пути.

Пример 4

Более десяти EKS-кластеров подняты на три мажорные версии

Кластеры отставали на несколько версий Kubernetes и платили надбавку за устаревшие версии. Поднял все кластеры через цепочку версий вместе с CNI, с репетицией на тестовом кластере и окнами до начала пиковой нагрузки; процедуру оформил в playbook и передал команде. Надбавка снята; на основных кластерах ни одного инцидента.

Пример 5

AWS-платформа: от bastion-хостов и статических ключей к OIDC и managed-сервисам

Компания с несколькими веб-продуктами на ECS и без документации по инфраструктуре. Спроектировал EKS-окружение с нуля как код (Argo CD, IRSA, CSI-драйверы для секретов и EFS, логи в OpenSearch, ExternalDNS), заменил bastion на ECS Exec, мигрировал базу на Aurora Serverless, перевёл репозитории на GitHub Actions с OIDC вместо статических ключей, поднял несколько site-to-site VPN с BGP и перенёс брокер сообщений с внешнего хостинга в AWS без инцидентов.

Пример 6

Единый deploy-flow для восьми репозиториев

Деплой-пайплайны восьми сервисов открывали MR в GitOps-репозиторий по-разному и застревали при параллельных деплоях. Перевёл их на общий CI-компонент с rebase-and-retry, проверил четырьмя одновременными деплоями, закрыл более ста зависших MR. Деплои больше не требуют ручного вмешательства.

Пример 7

Команда облачной платформы для B2B-продукта

Руководил командой из семи инженеров, строившей Kubernetes-платформу. Мигрировал production-кластеры с Docker на containerd, ввёл spot-флот для dev-окружений примерно за треть цены on-demand ноды, выделенные группы нод для критичных приложений, правила requests/limits и управления ёмкостью для всех команд, автоматическое обновление сертификатов через cert-manager, первый в компании Kubernetes-оператор на Go, managed Kafka с собственными дашбордами, GitOps на Argo CD и инфраструктуру как код на Terraform.

Разработка

Собственные проекты, показывающие, как я разрабатываю софт, а не только инфраструктуру.

Платформа сбора данных из 40+ разнородных источников

Python 3.12, PostgreSQL с TimescaleDB, Next.js, Docker Compose. Сборщики с контролем консистентности и восстановлением после сбоев, LLM-анализ со структурированным выходом, дайджесты и уведомления в Telegram. Более 250 SQL-миграций как единственный способ менять схему, записи архитектурных решений (ADR), тесты pytest и Playwright, деплой с откатом по SHA коммита.

Монитор видеоканалов с транскрибацией

Python, SQLite, Docker Compose. Приём по RSS, субтитры, где они есть, иначе распознавание речи на GPU (faster-whisper, whisper.cpp) с детекцией речи и подавлением галлюцинаций, суммаризация локальной LLM через Ollama, веб-интерфейс с OAuth. Все данные остаются в локальной сети; тюнинг ASR задокументирован.

CLI для секретов на macOS на Swift

Мастер-пароль менеджера паролей хранится в Data Protection Keychain и разблокируется по Touch ID; инструмент выдаёт постквантовый ключ age для SOPS. Без сети и телеметрии; модель безопасности задокументирована.

Методика сравнения LLM-агентов для кода

Одна задача, несколько агентов, замеры токенов, времени и расхода квот; результаты оценивает отдельный агент-судья по рубрике и сводит в отчёт. Нужна, чтобы выбирать инструменты по цифрам, а не по впечатлениям.
